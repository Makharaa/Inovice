# Makhara Invoice — ინსტალაცია FastPanel-ზე

## 1. დომენი და PHP

FastPanel-ში შექმენით საიტი:

- დომენი: `invoice.makhara.ge`
- PHP: 8.2 ან უფრო ახალი
- HTTPS: ჩართული

პროექტი ატვირთეთ, მაგალითად:

`/var/www/USERNAME/data/www/invoice.makhara.ge/`

საიტის Document Root აუცილებლად მიუთითეთ:

`/var/www/USERNAME/data/www/invoice.makhara.ge/public`

ეს მნიშვნელოვანია, რადგან `app`, `database` და `storage` საქაღალდეები საჯაროდ ხელმისაწვდომი არ უნდა იყოს.

## 2. მონაცემთა ბაზა

FastPanel-იდან შექმენით:

- ახალი MySQL მონაცემთა ბაზა;
- ამ ბაზისთვის ცალკე მომხმარებელი;
- ძლიერი პაროლი.

ბაზა უნდა იყოს ცარიელი. ცხრილებს ინსტალერი თავად შექმნის.

## 3. ფაილების უფლებები

ვებსერვერს `storage` საქაღალდეში ჩაწერა უნდა შეეძლოს. ჩვეულებრივ საკმარისია:

```bash
chmod 775 storage
chmod 775 storage/cache storage/logs
```

არ გამოიყენოთ `777`, თუ ჰოსტინგის კონფიგურაცია ამას არ მოითხოვს.

## 4. ინსტალერი

ბრაუზერში გახსენით:

`https://invoice.makhara.ge/install.php`

შეავსეთ:

- საიტის სრული მისამართი;
- ბაზის ჰოსტი და პორტი;
- ბაზის სახელი;
- ბაზის მომხმარებელი და პაროლი;
- პირველი ადმინისტრატორის სახელი, ელფოსტა და პაროლი.

ინსტალერი:

1. შეამოწმებს ბაზასთან კავშირს;
2. შექმნის ცხრილებს;
3. შექმნის ადმინისტრატორს;
4. შექმნის დაცულ `storage/config.php` ფაილს.

ინსტალერი უარს იტყვის მუშაობაზე, თუ ბაზაში უკვე არსებობს მომხმარებლები. თუ `storage/config.php` დაიკარგა, აღადგინეთ ის სარეზერვო ასლიდან ან `config/config.example.php`-ის საფუძველზე; ინსტალერის ხელახლა გაშვება საჭირო არ არის.

## 5. ინსტალაციის შემდეგ

აუცილებლად წაშალეთ:

`public/install.php`

შემდეგ შეამოწმეთ:

- ავტორიზაცია;
- გამცემის დამატება;
- მიმღების დამატება;
- სამივე ენაზე ინვოისის შექმნა;
- PDF ჩამოტვირთვა;
- მობილური ხედი.

## 5.1. Cloudflare / Reverse Proxy

თუ საიტი Cloudflare-ის (ან nginx-ის) უკან მუშაობს, PHP ყველა ვიზიტორს პროქსის IP-ით დაინახავს და შესვლის მცდელობების ლიმიტი **ყველასთვის საერთო** გახდება: ერთი კაცის შეცდომებმა შეიძლება ყველა დაბლოკოს. ამის თავიდან ასაცილებლად სისტემას უნდა ვუთხრათ, რომელ პროქსებს ენდოს.

### Cloudflare-ისთვის (რეკომენდებული გზა)

1. სერვერზე, პროექტის საქაღალდეში გაუშვით:

   ```bash
   php tools/cloudflare-trusted-proxies.php
   ```

   სკრიპტი Cloudflare-ის **ოფიციალურ, მიმდინარე** სიებს (`https://www.cloudflare.com/ips-v4` და `ips-v6`) ჩამოტვირთავს, შეამოწმებს და მზა ბლოკს დაბეჭდავს.
2. დაბეჭდილი `'trusted_proxies' => [ ... ],` ბლოკი ჩასვით `storage/config.php`-ში, `'app'` სექციაში (მაგალითად `'session_name'`-ის შემდეგ).
3. სკრიპტი სიას ავტომატურად ამატებს `127.0.0.1`-სა და `::1`-ს, რადგან nginx და PHP ხშირად ერთ სერვერზეა.
4. დააკვირდით, რომ ფაილში `trusted_proxies` ერთხელ იყოს. გადატვირთეთ PHP-FPM/OPcache.
5. **შემოწმება:** შედით სისტემაში, გახსენით „მომხმარებლები" (ადმინისტრატორით). „ბოლო შესვლის" ქვეშ უნდა ჩანდეს **თქვენი რეალური საჯარო IP**. თუ ჩანს `127.0.0.1`, `172.x.x.x` ან `104.x.x.x`, პროქსი სიაში არ არის: შეამოწმეთ, რომელი IP ჩანს და დაამატეთ.

Cloudflare ახალ დიაპაზონებს იშვიათად ამატებს. თუ ახალი დიაპაზონი სიაში არ არის, სისტემა უსაფრთხოდ ბრუნდება ძველ ქცევაზე (პროქსის IP-ს გამოიყენებს), ამიტომ სკრიპტის ხელახლა გაშვება რამდენიმე თვეში ერთხელ ღირს.

### სხვა პროქსი

`storage/config.php`-ში `app` სექციაში ხელით ჩაწერეთ მხოლოდ საკუთარი პროქსის IP-ები ან CIDR დიაპაზონები:

```php
'trusted_proxies' => ['127.0.0.1', '203.0.113.0/24'],
```

მხოლოდ ამ მისამართებიდან მოსულ `X-Forwarded-For` სათაურს ენდობა სისტემა. თუ პროქსი არ გაქვთ, სია ცარიელი დატოვეთ.

### Cloudflare-ის პარამეტრები

- **SSL/TLS რეჟიმი:** `Full (strict)`; `Flexible` რეჟიმი უსაფრთხო არ არის და გადამისამართების ციკლს იწვევს.
- **გამორთეთ** `Rocket Loader`, `Auto Minify` (JavaScript) და `Email Address Obfuscation`: ისინი გვერდში საკუთარ სკრიპტებს ამატებენ ან არსებულს ცვლიან, რასაც უსაფრთხოების პოლიტიკა (CSP) დაბლოკავს.
- **Web Analytics-ის ავტომატური ჩართვა** (`static.cloudflareinsights.com`) CSP-ით დაიბლოკება: ეს მხოლოდ კონსოლის შეტყობინებაა და სისტემის მუშაობაზე არ მოქმედებს. თუ გსურთ, გამორთეთ ავტომატური ინექცია.
- **Cache:** HTML გვერდებს სისტემა თავად აქცევს `no-store`-ად; არ შექმნათ Cache Rule, რომელიც ინვოისების გვერდებს ქეშავს.

## 6. სარეზერვო ასლი

რეგულარულად შეინახეთ:

- MySQL მონაცემთა ბაზის Dump;
- `storage/config.php`.

ინვოისის ისტორიის ძირითადი მონაცემები ბაზაში ინახება. PDF საჭიროებისას თავიდან გენერირდება უცვლელი Snapshot მონაცემებით.

## 7. განახლება

განახლებამდე ყოველთვის შექმენით ბაზისა და პროექტის სრული სარეზერვო ასლი. `storage/config.php` არ ჩაანაცვლოთ, რადგან მასში სერვერის მიმდინარე პარამეტრები ინახება.
