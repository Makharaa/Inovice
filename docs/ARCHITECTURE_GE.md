# ტექნიკური არქიტექტურა

## სტეკი

- PHP 8.2+
- PDO / MySQL
- HTML5 / CSS3
- მოდულური Vanilla JavaScript
- `html2pdf.js` — PDF-ის ბრაუზერში გენერირებისთვის

სერვერზე Composer ან Node.js საჭირო არ არის. მესამე მხარის PDF ბიბლიოთეკა უკვე შედის `public/assets/vendor` საქაღალდეში.

## საქაღალდეები

- `app/Core` — Router, Database, Auth, CSRF და სხვა ბირთვი;
- `app/Controllers` — HTTP მოთხოვნების მართვა;
- `app/Models` — მონაცემთა ბაზის მოთხოვნები;
- `app/Services` — ინვოისის ნომერი, გამოთვლები და შენახვის ტრანზაქციები;
- `app/Views` — ინტერფეისი და ინვოისის შაბლონები;
- `app/Lang` — ინვოისის ქართული, ინგლისური და რუსული ტექსტები;
- `database` — საწყისი სქემა;
- `public` — ერთადერთი საჯარო საქაღალდე;
- `storage` — სერვერის კონფიგურაცია, Cache და Log;
- `tests` — ძირითადი გამოთვლების ტესტები.

## მონაცემების გამიჯვნა

ყველა გამცემს, მიმღებსა და ინვოისს აქვს `user_id`. ჩვეულებრივი მომხმარებლის ყველა მოთხოვნა იზღუდება მიმდინარე მომხმარებლის ID-ით.

ადმინისტრატორს შეუძლია:

- მომხმარებლების მართვა;
- ყველა მომხმარებლის ინვოისების ნახვა;
- საკუთარი გამცემებითა და მიმღებებით ინვოისების შექმნა.

სხვა მომხმარებლის ინვოისის რედაქტირება ან წაშლა ადმინისტრატორსაც არ შეუძლია, რათა პასუხისმგებლობა და მონაცემების მფლობელობა არ აირიოს.

## Snapshot

ინვოისის შექმნისას გამცემისა და მიმღების მონაცემები JSON Snapshot-ად ინახება. მოგვიანებით კლიენტის ან კომპანიის მისამართის შეცვლა ძველ ინვოისს არ შეცვლის.

## ნუმერაცია

ნომრის ფორმატი:

`PREFIX-YEAR-0001`

ნუმერაცია დამოუკიდებელია თითოეულ გამცემზე და ახალ კალენდარულ წელს ავტომატურად იწყება `0001`-დან. ნომრის დაჯავშნა და ინვოისის შენახვა ერთ მონაცემთა ბაზის ტრანზაქციაში ხდება.

## დღგ-ის გამოთვლა

თუ გამცემი დღგ-ის გადამხდელი არ არის, დღგ-ის ველები საერთოდ არ ჩანს.

თუ გამცემი დღგ-ის გადამხდელია:

- ფასები დღგ-ის გარეშე — 18% ემატება ფასს;
- ფასები დღგ-ის ჩათვლით — 18% გამოიყოფა მითითებული ფასიდან.

გამოთვლები სერვერზე მეორდება. JavaScript-ის ცოცხალი ჯამი მხოლოდ მომხმარებლისთვის სწრაფი წინასწარი ჩვენებაა და მონაცემთა ბაზის საბოლოო თანხის წყარო არ არის.

## უსაფრთხოება

- `password_hash()` / `password_verify()`;
- PDO Prepared Statements;
- CSRF დაცვა ყველა ცვლილებაზე;
- ავტორიზაციის შემდეგ Session ID-ის განახლება;
- Login throttling: 5 მცდელობა / 15 წუთი;
- Soft Delete;
- საკუთრების შემოწმება ყველა ჩანაწერზე;
- გამონაკლისების ტექნიკური დეტალები მომხმარებელს არ ეჩვენება.
